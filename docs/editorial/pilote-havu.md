# Pilote Havu

La communauté Havu est la première communauté pilote d'URITHI (§75). Le pilote sert à **éprouver la méthode** (formulaires, catégories, circuit de validation, consentements, conservation) avant de l'étendre aux autres communautés.

> Le pilote ne doit pas prétendre représenter toute la diversité Havu à partir de quelques témoignages, et aucun témoignage ni aucune tradition ne doit être inventé pour donner l'impression d'un dossier complet (§75, §83).

## État initial dans URITHI
Créé par `npm run seed` :
- fiche communauté **Havu**, **non publiée**, état « Documentation non commencée » ;
- localisations de départ : territoires d'**Idjwi** et de **Kalehe** (Sud-Kivu) ;
- langue de départ : **Kihavu** (code ISO 639-3 `hav`) ;
- questionnaire général de collecte.

Ces localisations et cette langue sont des **références de départ à confirmer et à sourcer** pendant le pilote, puis à corriger si nécessaire.

## Étapes proposées
1. **Préparer** : nommer un responsable de collecte, créer les comptes des collecteurs, transcripteurs, traducteurs et validateurs (dont au moins une personne compétente en kihavu).
2. **Recenser les sources existantes** (livres, articles, archives) dans le registre des sources, avec leurs droits.
3. **Créer une première mission** (Missions → Nouvelle mission) avec un objectif limité, par exemple deux ou trois thèmes : gastronomie, contes, dénominations et localisation.
4. **Collecter** selon le [protocole](protocole-national-de-collecte.md), avec les [questionnaires](questionnaires-de-terrain.md) adaptés et le [formulaire de consentement](formulaire-de-consentement.md) traduit.
5. **Traiter** : transcription, traduction, fiches, relations, variantes.
6. **Valider et publier** les premières fiches ; compléter et publier la fiche communauté lorsque ses informations de base sont sourcées.
7. **Tester la conservation** : sauvegarde, test de restauration, contrôle d'intégrité.
8. **Recueillir les retours** des personnes interrogées et de la communauté.
9. **Évaluer** avec la grille ci-dessous, puis corriger la méthode avant l'extension.

## Grille d'évaluation du pilote (§77)
| Critère | Question | Évaluation |
|---|---|---|
| Formulaires | Les collecteurs les remplissent-ils sans difficulté ? | |
| Qualité des données | Les fiches sont-elles complètes, précises, sourcées ? | |
| Traductions | Sont-elles claires pour un lecteur francophone ? | |
| Traçabilité des sources | Retrouve-t-on la provenance de chaque information ? | |
| Consentements | Sont-ils compris, complets, bien enregistrés ? | |
| Catégories | Sont-elles adaptées ? Faut-il en ajouter, en renommer ? | |
| Variantes | Les différences entre localités ou familles sont-elles bien documentées ? | |
| Validations | Les validateurs disposent-ils de ce qu'il faut pour décider ? | |
| Conservation | Les originaux sont-ils intacts ? La restauration fonctionne-t-elle ? | |
| Performance | Le site est-il rapide, y compris sur téléphone et connexion lente ? | |
| Mise à jour | Corriger et compléter une fiche est-il simple ? | |
| Compréhension | Un visiteur non spécialiste comprend-il les contenus ? | |
